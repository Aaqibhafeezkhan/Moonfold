# Launch plan: getting real stars and real users

Read this honestly first. Nobody can promise "number one trending". GitHub trending is a short-term velocity ranking: a burst of genuine stars in about a day. What you can control is a product with a sharp hook, a great first 30 seconds, and a concentrated launch week. This plan does that and nothing shady.

The market is crowded. T3 Code, its forks (Threadlines, OK Code and others), Conductor, Cursor and the official Codex app all exist. The hook has to be what none of them does well: your task keeps going across agents when a limit hits.

## 1. The pitch (use everywhere)

- One line: "Hit your Codex limit mid-task? One click, Claude Code (or Gemini CLI) continues with the same plan, diff and context."
- Second line: "Open-source workspace for every coding agent you already pay for."
- Proof: a 20 second GIF of the handoff on a real repo. This GIF is the product's entire marketing budget. Make it perfect.
- Credit T3 Code openly. Fork honesty earns respect; hiding it gets you called out.

## 2. Assets to have before launch

- README: GIF at the top, 3 bullet value props, install one-liner, provider support matrix (generated from tests), accurate fair comparison table, "how handoff works" diagram, FAQ, disclaimer, license and credits.
- Social preview image 1280x640, repo description, topics (ai-agents, coding-agent, codex, claude-code, gemini-cli, electron, mcp, developer-tools).
- 3 short demos: handoff, scheduled tasks plus browser pane, skills and plugin manager.
- Docs site on GitHub Pages, CHANGELOG, ROADMAP, CONTRIBUTING, 15 seeded good-first-issues, Discussions on, Discord or GitHub Discussions only (pick one).
- Release v0.1.0-beta.1 with installers for all three OSes and checksums.

## 3. Timeline

T minus 14 to 7 days: private beta
- Recruit 20 to 30 testers from the places the users already are: r/ClaudeAI, r/OpenAI, r/ChatGPTCoding, the T3, Claude Code and Codex Discords, X, LinkedIn. Ask for bugs, not stars.
- Fix everything that breaks the first 5 minutes. Install friction kills launches.

T minus 7 to 1 days
- Record the final GIF and videos. Write the posts below. Line up 5 to 10 real developers who will try it on launch day and comment honestly (no scripts, no asking for upvotes in a coordinated way).

Launch day (Tuesday to Thursday, around 14:00 to 16:00 Berlin time to hit US morning)
1. Tag the release, flip the repo to polished state.
2. Show HN: "Show HN: <name>, an open-source workspace where your coding task survives agent usage limits". Put the GIF and the honest limits in the first comment. Be present for hours answering.
3. X thread (GIF first, then three features, then repo link).
4. LinkedIn post with the GIF (you already have a developer audience there; this is your strongest owned channel). Write it as a build story: why you made it, what broke, what you learned.
5. Reddit: one post per relevant subreddit, each written for that audience, read each sub's self-promotion rules first. Never copy-paste the same post.
6. Product Hunt on a separate day within the same week, so you get two spikes instead of one.
7. YouTube: a 5 to 8 minute demo and build-story video on your channel, link in the repo.

T plus 1 to 30 days
- Answer every issue in under 24 hours for the first two weeks. Ship a patch release within 3 days with a visible changelog. Thank bug reporters publicly.
- Blog post (dev.to and your site): "How I made coding agents hand off context when limits hit". Technical posts keep paying stars for months.
- Submit to relevant awesome lists, directories and newsletters (each has its own rules, read them).
- Weekly release rhythm for a month. Visible momentum draws contributors.

## 4. What not to do

- Do not buy stars, trade stars, use bots, sock puppets or fake accounts. GitHub removes them, fake-star detection tools exist, and one exposure ends your credibility. It also violates GitHub's terms.
- Do not mass-DM, spam subreddits or cross-post identical text.
- Do not claim parity, speed or support you have not measured. The provider matrix comes from tests that ran.
- Do not imply OpenAI, Anthropic, Google, Cursor or T3 endorse you.

## 5. Metrics to watch

Stars per day, clones, release downloads per OS, time to first successful task (from analytics only if users opted in, otherwise from tester interviews), issues opened versus closed, percentage of issues that are install problems (this should fall every release).

## 6. Realistic expectations

A genuinely useful, polished open-source tool with a clear demo can pick up real traction in the first week. Reaching trending depends on timing and competition that week, and on how many of your first-day visitors actually star. Treat the star count as a result of product quality and launch execution, and plan to keep shipping for months. The star goal is yours to chase, the plan above is the honest way to chase it.
